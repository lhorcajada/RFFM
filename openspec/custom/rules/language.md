# OpenSpec Language

## Required Language

All newly created or modified OpenSpec change artifacts MUST be written in English. This requirement applies to proposals, specifications, designs, task lists, implementation notes, interfaces, reviews, security notes, performance notes, accessibility notes, and change overviews. Existing historical artifacts do not need to be rewritten unless they are modified.

The following rules apply:

- Use English for narrative text, headings, checklists, acceptance criteria, research notes, and validation evidence.
- Preserve source-code identifiers, file paths, endpoint routes, enum values, error codes, payload field names, and other technical literals exactly as they appear in the system.
- Localized user-facing strings MAY be documented in their target language when the change requires them, but the surrounding explanation MUST remain in English.
- Quoted external text MAY remain in its original language when necessary, but the artifact MUST identify it as a quotation and explain its relevance in English.
- Agents MUST apply this rule when creating or updating OpenSpec artifacts and MUST report or correct language violations during validation.
